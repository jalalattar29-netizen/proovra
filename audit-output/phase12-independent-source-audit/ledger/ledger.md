ROOT CAUSE: the transport classifier had TWO buckets — retryable and not — and put `timeout` and `fetch_error` in "retryable". That is a claim the transport never made. A timeout means the request was WRITTEN and the answer was lost; the receiver may well have processed it. So an ambiguous webhook was re-sent after 30 s, and for a webhook whose purpose is to trigger downstream work that is a real duplicate action, not a retry. FIX: three buckets, and the distinction between the first two is whether the transport can PROVE nothing committed. NO_COMMIT (connection refused, DNS failure, TLS failure, or a receiver that ANSWERED 503/429) is the only family that may resend. AMBIGUOUS (timeout, reset, hang-up, or anything unrecognised — the default, deliberately) gets its own non-terminal state, its own bounded reconciliation policy (3 passes, 60/300/900 s), and its own terminal DEAD_LETTERED_UNKNOWN, which is NOT the same as FAILED because "the receiver refused" and "we never found out" are different facts an operator acts on differently. `deliverWebhookOnce` now reports the underlying syscall rather than collapsing everything to two strings. The action idempotency key stays attached throughout, so if a provider lookup ever establishes that nothing committed, the resend is the SAME intent. |
| NEW-016 | MEDIUM | DISCOVERED_THIS_PASS | PASS | PASS | PARTIAL | NOT_APPLICABLE | **FIXED_VERIFIED** | NONE. ROOT CAUSE: both status columns were VARCHAR(20), sized when the longest value was `RETRY_SCHEDULED`. `DEAD_LETTERED_UNKNOWN` is 21 characters. The widened CHECK therefore accepted a value the COLUMN refused, and PostgreSQL raised value-too-long — which the fenced updater caught and reported as `false`, the same answer it gives for an honest zero-row match. The reconciler read that as "another worker got there first", left the row AMBIGUOUS, and revisited it on every tick forever without ever terminating it. TWO fixes, both real: (1) widen both columns to VARCHAR(32) in the same EXPAND migration, which is safe by construction because every value that fit still fits; (2) the fenced updater now DISTINGUISHES a rejected write from a zero-row match and emits an operator-visible event with the error NAME (never the message, which can carry row contents) before returning false. The second is the load-bearing one: without it a broken deployment looks exactly like healthy contention, and this defect was findable only because that distinction was made first. |
