# Detached Custody Attestation Verification (External)

**Audience:** anyone outside PROOVRA who needs to verify a custody event's detached attestation.

---

## 1. What you receive

For each custody event with an attestation:

- The custody event record (id, evidenceId, eventType, atUtc, sequence, prevEventHash, eventHash).
- The detached attestation envelope (see `docs/security/custody-attestations.md` §3).
- The signer's public material reference (e.g. a KMS `GetPublicKey` URL or a published PEM).

## 2. Verification steps

```python
# Python pseudo-code — adapt to your language of choice
import json, hashlib
from cryptography.hazmat.primitives.serialization import load_pem_public_key
from cryptography.hazmat.primitives.asymmetric.ed25519 import Ed25519PublicKey

def canonical(obj):
    """Sorted-key canonical JSON, no whitespace."""
    return json.dumps(obj, sort_keys=True, separators=(",", ":"))

def verify(custody_event, attestation, public_key_pem):
    canonical_payload = {
        "custodyEventId": custody_event["id"],
        "evidenceId":     custody_event["evidenceId"],
        "eventType":      custody_event["eventType"],
        "atUtc":          custody_event["atUtc"],
        "sequence":       custody_event["sequence"],
        "prevEventHash":  custody_event.get("prevEventHash"),
        "eventHash":      custody_event.get("eventHash"),
    }
    recomputed_hash = hashlib.sha256(canonical(canonical_payload).encode()).hexdigest()
    if recomputed_hash != attestation["canonicalPayloadHash"]:
        return "payload_hash_mismatch"

    pk = load_pem_public_key(public_key_pem.encode())
    if not isinstance(pk, Ed25519PublicKey):
        return "unsupported_algorithm"

    try:
        sig = bytes.fromhex(attestation["canonicalPayloadHash"])  # message that was signed
        # Note: PROOVRA signs the hex digest as RAW bytes via Ed25519.
        # See `services/api/src/signing/kms-signer.ts` and `services/api/src/crypto.ts`.
        import base64
        pk.verify(base64.b64decode(attestation["signature"]), sig)
        return "verified"
    except Exception:
        return "signature_invalid"
```

## 3. Allowed outcomes

The verification procedure produces one of the 7 bounded outcomes documented in `docs/security/custody-attestations.md` §4.

## 4. What attestations prove

- That the recorded signer (at the recorded `keyVersion`) signed a hash of the canonical payload.
- That the canonical payload as recomputed now matches the hash that was signed.

## 5. What attestations DO NOT prove

- They do NOT prove the underlying evidence is authentic.
- They do NOT prove the operator who triggered the custody event was authorised.
- They do NOT carry any legal-admissibility claim.

## 6. Public material rotation

If PROOVRA rotates the signer's underlying key material and you only have the OLD attestation:

- The attestation can still be verified IF the old public key is preserved (published in PROOVRA's signer governance docs or AWS KMS console).
- If the old public key is destroyed, the attestation becomes unverifiable. This is documented as a known risk in `docs/security/key-rotation.md` §4.

## 7. Where to find the attestation set inside a Verification Package (P3.1.1)

Packages generated by PROOVRA workers at P3.1.1 and later carry the bounded attestation set directly inside the ZIP:

- `custody/attestations.json` — the deterministic attestation set (sorted by `custodyEventSequence ASC`).
- `custody/attestation-verification.md` — the in-package copy of this procedure, frozen at generation time.
- `signers/signer-registry-snapshot.json` — the signer state at generation time (provider, keyId, keyVersion, algorithm, verification material reference).

Old packages (generated before P3.1.1) do NOT carry these files. Their absence is not a verification failure — it simply means the verifier must call the live api endpoints documented in §2 above to obtain the attestations.

See `docs/verification/verification-package-format.md` for the full schema.
