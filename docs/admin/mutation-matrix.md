## NOT_APPLICABLE, with reasons

- `POST /v1/admin/incidents/:id/acknowledge` on `/admin/operations` — confirmation: Acknowledging marks an incident as seen by an operator and nothing else: it stays OPEN-equivalent (ACKNOWLEDGED), can still be resolved or reassigned, has no external, billing, evidence, custody or customer effect, and is limited to the row the operator is looking at. A dialog on every acknowledgement would be pure confirmation fatigue on the most frequent triage click.
- `POST /v1/admin/incidents/:id/assign` on `/admin/operations` — confirmation: Assigning an incident to yourself, or returning it to the unassigned queue, is immediately reversible by the same button, affects only the visible row, and has no external, billing, evidence, custody, security or customer consequence. It is the operator's own work-claim, not a decision about the condition.
- `POST /v1/operations/custody-attestations/:id/verify` on `/admin/platform/signers` — confirmation: Verification recomputes and displays a report for one attestation; the handler writes no row, changes no evidence, custody, TSA or report state, and reaches no external provider. Running it twice returns the same report. It is a read expressed as POST because it carries a workspace-scoped body, and a confirmation dialog would add a step to an action that changes nothing.
- `POST /v1/operations/exports/:id/verify` on `/admin/platform/exports` — confirmation: Reproducibility verification recomputes the export's manifest hash and compares it; the export, its artifacts and retention are not modified, no provider is called, and repeating it produces the same report (only an informational security event per run). The report is the point of the action and a dialog before a read-only check would add nothing an operator could decide.
- `POST /v1/operations/signers/:id/preview` on `/admin/platform/signers` — confirmation: The preview computes what a rotation WOULD do for one signer and shows the plan; the handler persists nothing, changes no key state and contacts no provider beyond a read. Repeating it yields the same plan. The mutations it previews (promote, retire, revoke) each carry their own confirmation and step-up.
