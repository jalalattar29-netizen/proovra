# Phase 20 — Route Permission Matrix

Operator-readable inventory of the riskiest API surfaces and their gates as of Phase 20. Source of truth: the route files themselves. This document is generated by hand from the audit; every row links to file:line for re-verification.

## Legend

- **Auth**: `requireAuth` (session JWT, Phase 0+) | `requireApiKey` (service-account Bearer, Phase 10) | `requireIntegrationCronSecret` (cron, Phase 12) | `signature` (Twilio/webhook signature, Phase 18) | `public` (no preHandler).
- **Anti-enum**: `404` returned on non-member instead of 403 (Phase 11+ anti-enumeration posture).
- **Permission**: the canonical `identity.*` / `governance.*` / `evidence.*` / `integration.*` permission gate.
- **Step-up**: `requireStepUpForSensitiveAction` purpose (Phase 19), or `—` when not applicable.
- **Governance gate**: legal hold / publication / retention / review gate consulted (Phase 9, 14).

## Hard invariants (cross-cutting)

1. **404 on non-member**: every operator route gates membership before permission. Non-members get `{ error: { code: "not_found" } }` — never 403.
2. **Service accounts never get step-up**: step-up uses session JWT identity. Service accounts use the Phase 17 hardening + IP allowlist.
3. **Contributors never get workspace MFA**: contributor verification uses Phase 18 Verify + the `CONTRIBUTOR_PHONE_VERIFICATION` step-up purpose only.
4. **Public verify isolation**: regression tests assert public verify does NOT read any Phase 17 / 18 / 19 / 20 table.
5. **Cron secret reuse**: `INTEGRATION_CRON_SECRET` protects Phase 12 reliability, Phase 18 communications retries, Phase 19 identity-security reconcile, and Phase 20 master reconcile.
6. **Step-up failure response**: always `{ error: { code: "STEP_UP_REQUIRED", ... } }` with HTTP 401 (matches the `ErrorCode.STEP_UP_REQUIRED` mapping).
7. **High-risk action block**: CRITICAL risk level returns HTTP 403 `HIGH_RISK_ACTION_BLOCKED`; the action never reaches the mutation path.
